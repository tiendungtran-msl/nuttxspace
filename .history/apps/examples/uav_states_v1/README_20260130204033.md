# UAV Attitude Application

Real-time attitude estimation system for STM32H743 with 4x ICM-42688-P IMUs.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                    UAV Attitude Application                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐                                               │
│  │ Sensor Task  │  Priority: 120  Rate: 400 Hz                  │
│  │ (pthread)    │                                               │
│  └──────┬───────┘                                               │
│         │ publish                                                │
│         ▼                                                        │
│  ┌──────────────────────────────┐                               │
│  │   ORB: sensor_imu[0..3]      │  Thread-safe ring buffer      │
│  └──────────────┬───────────────┘                               │
│                 │ subscribe                                      │
│                 ▼                                                │
│  ┌──────────────┐                                               │
│  │ Estimator    │  Priority: 110  Rate: 100 Hz                  │
│  │ Task         │  PX4-style quaternion filter                  │
│  └──────┬───────┘                                               │
│         │ publish                                                │
│         ▼                                                        │
│  ┌──────────────────────────────┐                               │
│  │   ORB: vehicle_euler[0..3]   │  Roll, Pitch, Yaw + Bias      │
│  └──────────────┬───────────────┘                               │
│                 │ subscribe                                      │
│                 ▼                                                │
│  ┌──────────────┐                                               │
│  │ Telemetry    │  Priority: 90   Rate: 50 Hz                   │
│  │ Task         │  UART output for visualization                │
│  └──────┬───────┘                                               │
│         │                                                        │
│         ▼                                                        │
│  ┌──────────────┐                                               │
│  │ UART /dev/   │  115200 baud, separate from console           │
│  │ ttyS1        │                                               │
│  └──────┬───────┘                                               │

          │
          ▼

│ Python Ground    │  tools/uav_ground_station.py

└──────────────────┘
```

## Key Design Principles

1. **No printf in high-rate tasks** - Avoid UART blocking
2. **Separate telemetry UART** - Not the console (prevents lag)
3. **pthread with priorities** - Real-time scheduling
4. **ORB pub-sub** - Thread-safe data sharing

## Usage

### On NuttX Console

```bash
# Run main application (telemetry on /dev/ttyS1)
nsh> uav_attitude

# Specify different telemetry UART
nsh> uav_attitude -t /dev/ttyS2

# Show help
nsh> uav_attitude -h
```

### Python Ground Station

```bash
# Install dependencies
pip3 install pygame pyserial

# Run with serial port
python3 tools/uav_ground_station.py --port /dev/ttyUSB0

# Simulation mode (no hardware)
python3 tools/uav_ground_station.py --sim

# Interactive port selection
python3 tools/uav_ground_station.py
```

## Protocol

Telemetry output format (UART @ 115200 baud):

```
ATT,<imu_id>,<roll>,<pitch>,<yaw>,<bias_x>,<bias_y>,<bias_z>\n
```

- `imu_id`: 0-3 (which IMU)
- `roll, pitch, yaw`: Degrees
- `bias_x, bias_y, bias_z`: Gyro bias (rad/s)

## Task Priorities

| Task | Priority | Rate | Purpose |
|------|----------|------|---------|
| Sensor | 120 | 400 Hz | Read IMUs, publish sensor_imu |
| Estimator | 110 | 100 Hz | Compute attitude, publish vehicle_euler |
| Telemetry | 90 | 50 Hz | Send UART for visualization |

Higher priority = runs first when multiple tasks ready.

## Console Lag Prevention

Previous versions caused console lag because:
1. High-rate printf() blocked UART
2. Tasks running in tight loops with usleep()
3. Console UART conflict with telemetry

This version fixes it by:
1. Minimal console output (status every 5 seconds)
2. Separate UART for telemetry (/dev/ttyS1)
3. Proper pthread with SCHED_FIFO priorities
4. Non-blocking UART writes for telemetry
